# Regeln aus ui-skills übernommen (25.11.2026)

## Frage
Hilft ui-skills (github.com/ibelick/ui-skills, MIT) dem Tracker, zusätzlich zu den Regeln aus Apples HIG (`2026-11-25-apple-hig.md`)?

## Befund
- Elf Skills mit kurzen MUST/NEVER-Regeln für Webcode. Kein Designsystem
- Die HIG sagen, was gut ist. ui-skills sagt, wie man es im Browser sauber baut. Das ergänzt sich
- Viele Regeln setzen Tailwind, React, `motion/react` und Base UI voraus. Der Tracker nutzt Astro mit eigenem CSS

## Entscheidung
In eigenen Worten übernommen nach `docs/DESIGN.md`, Abschnitt "Ergänzung 25.11.: Umsetzung im Browser":
- fixing-motion-performance: fast ganz, weil die 3D-Szene und das Glas-HUD genau diese Risiken haben
- fixing-accessibility: fast ganz, als Web-Umsetzung des HIG-Abschnitts
- baseline-ui: nur `dvh`, Safe Area, feste z-index-Ebenen, quadratische Elemente
- fixing-metadata: Open Graph, theme-color, keine erfundenen strukturierten Daten. Indexierung bleibt offen für Checkpoint C

## Nicht übernommen
- Tailwind, `cn`, `motion/react`, `tw-animate-css`, Base UI, Radix: anderer Stack
- "Keine eigene Easing-Kurve": der Tracker hat bewusst eine, `cubic-bezier(0.22,1,0.36,1)`
- "Keine Verläufe": der Verlauf im H1 ist gewollt
- "Höchstens 200 ms für Feedback": Farbwechsel bleiben bei 300 ms
- "Keine Animation, wenn nicht verlangt": zu streng für einen Live-Tracker, stattdessen gilt "Bewegung nur mit Zweck" aus dem HIG-Abschnitt
- `AlertDialog` für Löschen: Komponente aus React-Bibliotheken. Das Prinzip (Bestätigung vor Unumkehrbarem) gilt trotzdem
- create-canvas, component-canvas, device-frames, create-design-md, improve-ui: bauen Mockups oder eine neue DESIGN.md, die es schon gibt

## Folgen
- Am Code nichts geändert. `Base.astro` hat schon `lang="de"`, `noindex` als Standard, `og:title`, `og:description`, `og:type`. Es fehlen `og:image`, `og:url`, `twitter:card` und `theme-color`
- Die z-index-Tokens kommen mit dem HUD
